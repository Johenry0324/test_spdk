## 目標讀者 {#blob_pg_audience}

程式設計師指南面向編寫利用 SPDK Blobstore 的應用程式的開發人員。它旨在
補充源代碼，提供如何將 Blobstore 集成到
應用程式中的整體理解，以及提供一些關於 Blobstore 在幕後如何工作的高級見解。它不
旨在作為設計文檔或 API 參考，在某些情況下將討論源代碼片段和高級
序列；有關最新源代碼參考，請參閱 [repo](https://github.com/spdk)。

## 簡介 {#blob_pg_intro}

Blobstore 是一個持久、斷電安全的塊分配器，設計用於作為本地存儲系統
支持更高級別的存儲服務，通常代替傳統文件系統。這些更高級別的服務
可以是本地數據庫或鍵/值存儲（MySQL、RocksDB），它們可以是專用設備（SAN、NAS），或
分佈式存儲系統（例如 Ceph、Cassandra）。但是，它不設計為通用文件系統，
並且故意不符合 POSIX。為了避免混淆，我們避免引用文件或對象，而是
使用術語 'blob'。Blobstore 設計為允許對稱為 'blobs' 的塊設備上的塊組進行異步、未快取、並行讀取和寫入。
Blobs 通常很大，至少以數百
千字節為單位測量，並且始終是底層塊大小的倍數。

Blobstore 主要設計為在"下一代"媒體上運行，這意味著設備支持快速隨機
讀取和寫入，無需後台垃圾回收。但是，在實踐中，該設計在
NAND 上也運行良好。

## 操作理論 {#blob_pg_theory}

### 抽象

Blobstore 定義了如下所示的存儲抽象層次結構。

* **邏輯塊**：邏輯塊由磁盤本身公開，從 0 到 N 編號，其中 N 是
  磁盤中的塊數。邏輯塊通常是 512B 或 4KiB。
* **頁面**：頁面定義為在 Blobstore 創建時定義的固定數量的邏輯塊。組成
  頁面的邏輯塊始終是連續的。頁面也從磁盤的開頭編號，這樣
  第一個頁面值的塊是頁面 0，第二個頁面是頁面 1，等等。頁面通常大小為 4KiB，
  所以在實踐中這是 8 或 1 個邏輯塊。SSD 必須能夠執行至少頁面大小的原子讀取和寫入。
* **集群**：集群是在 Blobstore 創建時定義的固定數量的頁面。組成集群的頁面
  始終是連續的。集群也從磁盤的開頭編號，其中集群 0 是第一個集群
  值的頁面，集群 1 是第二組頁面，等等。集群通常大小為 1MiB，或 256 頁。
* **Blob**：blob 是集群的有序列表。Blobs 由應用程式
  操作（創建、調整大小、刪除等），並在斷電和重啟後持續存在。應用程式使用 Blobstore 提供的標識符來訪問特定的 blob。
  Blobs 通過指定從 blob 開頭的偏移量以頁面為單位讀取和寫入。應用程式還可以
  以鍵/值對的形式為每個 blob 存儲元數據，我們將其稱為 xattrs（擴展屬性）。
* **Blobstore**：已由基於 Blobstore 的應用程式初始化的 SSD 被稱為"Blobstore"。
  Blobstore 擁有整個底層設備，該設備由私有 Blobstore 元數據區域和
  由應用程式管理的 blob 集合組成。

```text
+-----------------------------------------------------------------+
||                              Blob                               |
|| +-----------------------------+ +-----------------------------+ |
|| |           Cluster           | |           Cluster           | |
|| | +----+ +----+ +----+ +----+ | | +----+ +----+ +----+ +----+ | |
|| | |Page| |Page| |Page| |Page| | | |Page| |Page| |Page| |Page| | |
|| | +----+ +----+ +----+ +----+ | | +----+ +----+ +----+ +----+ | |
|| +-----------------------------+ +-----------------------------+ |
+-----------------------------------------------------------------+
```

### 原子性

對於所有關於原子性的 Blobstore 操作，都依賴於底層設備來保證至少一個頁面大小的原子
操作。這裡的原子性可以指多個操作：

* **數據寫入**：對於數據寫入的情況，原子性的單位是一個頁面。因此，如果正在進行大於一個頁面的寫入操作並且系統遭受斷電，
  媒體上的數據將在頁面
  大小粒度上保持一致（如果在斷電時正在更新單個頁面，則該頁面位置的數據
  將與斷電恢復後寫入操作開始之前的數據相同。）
* **Blob 元數據更新**：每個 blob 都有自己的元數據集（xattrs、大小等）。出於性能原因，此
  元數據的副本保存在 RAM 中，僅在應用程式進行顯式調用以
  這樣做時，或在卸載 Blobstore 時與磁盤版本同步。因此，例如，設置 xattr 在調用
  同步它（稍後介紹）之前是不一致的，但是，這是原子執行的。
* **Blobstore 元數據更新**：Blobstore 本身有自己的元數據，與每個 blob 元數據一樣，在
  RAM 和磁盤上都有副本。但是，與每個 blob 元數據不同，Blobstore 元數據區域不會通過 blob
  同步調用變得一致，它僅在通過 API 正確卸載 Blobstore 時同步。因此，如果 Blobstore
  元數據已更新（blob 創建、刪除、調整大小等）並且未正確卸載，它將需要執行一些額外的
  步驟，下次加載時將比乾淨關閉時花費更多時間，但不會有
  不一致。

### 回調

Blobstore 是回調驅動的；如果任何 Blobstore API 無法取得進展，它將
不會阻塞，而是在該點返回控制，並在原始調用完成時對 API 中提供的回調函數進行調用，以及
參數。回調將在進行調用的同一線程上進行，稍後更多關於
線程的內容。但是，某些 API 不提供回調參數；在這些情況下，調用是完全同步的。利用回調的
異步調用的範例包括涉及磁盤 IO 的調用，例如，在 IO 完成之前需要進行一些輪詢。
