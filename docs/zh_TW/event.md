# 事件框架 {#event}

SPDK 提供了一個用於編寫異步、輪詢模式、
無共享服務器應用程式的框架。事件框架旨在成為
可選的；大多數其他 SPDK 組件設計為集成到
應用程式中，而不特別依賴 SPDK 事件函式庫。該
框架定義了幾個概念 - 反應器、事件和輪詢器 - 這些概念在
以下章節中描述。事件框架為每個
核心生成一個線程（反應器），並使用無鎖隊列連接線程。訊息
（事件）然後可以在線程之間傳遞。在現代 CPU 架構上，
訊息傳遞通常比傳統鎖定快得多。有關
此框架理論基礎的討論，請參閱 @ref
concurrency。

事件框架公共介面在 event.h 中定義。

## 事件框架設計考慮 {#event_design}

簡單的服務器應用程式可以以單線程方式編寫。這
允許直接維護狀態而無需任何鎖定或
其他同步的代碼。但是，為了擴展（例如，允許更多
同時連接），應用程式可能需要使用多個線程。
在每個連接都獨立於所有其他
連接的理想情況下，應用程式可以通過創建額外的線程並
將連接分配給它們來擴展，而不引入跨線程
同步。不幸的是，在許多實際情況下，連接
並不完全獨立，跨線程共享狀態是必要的。SPDK
提供了一個事件框架來幫助解決這個問題。

## SPDK 事件框架組件 {#event_components}

### 事件 {#event_component_events}

為了在最小化同步
開銷的同時完成跨線程通信，框架以事件的形式提供訊息傳遞。
事件框架為每個 CPU 核心運行一個事件循環線程。這些線程是
稱為反應器，它們的主要職責是處理來自隊列的傳入事件。
每個事件由一個捆綁的函數指針及其
參數組成，目標是特定的 CPU 核心。事件是使用
spdk_event_allocate() 創建的，並使用 spdk_event_call() 執行。與
每連接一個線程的服務器設計不同，該設計通過依賴
操作系統將許多發出阻塞 I/O 的線程調度到
有限數量的核心上來實現並發，事件驅動模型需要使用明確的
異步操作來實現並發。異步 I/O 可以通過
非阻塞函數調用發出，完成通常使用
回調函數發出信號。

### 反應器 {#event_component_reactors}

每個反應器都有一個無鎖隊列，用於傳入到該核心的事件，並且
來自任何核心的線程可以將事件插入任何其他核心的隊列中。
運行在每個核心上的反應器循環檢查傳入事件並按
接收順序以先進先出順序執行它們。事件函數應該
永遠不阻塞，並且最好執行得非常快，因為它們是
直接從目標核心上的事件循環調用的。

### 輪詢器 {#event_component_pollers}

該框架還定義了另一種類型的函數，稱為輪詢器。輪詢器
可以使用 spdk_poller_register() 函數註冊。輪詢器，
像事件一樣，是帶有參數的函數，可以捆綁和執行。
但是，與事件不同，輪詢器會重複執行直到註銷，並且
在註冊它們的線程上執行。反應器事件循環
將對輪詢器的調用與其他事件處理交錯。輪詢器
旨在輪詢硬體作為中斷的替代。通常，輪詢器
在主事件循環的每次迭代中執行。如果不需要低延遲，輪詢器也可以
安排在定時器上定期執行。

### 應用程式框架 {#event_component_app}

框架本身被打包到稱為"app"的更高级別的抽象中。一旦
調用 spdk_app_start()，它將阻塞當前線程，直到應用程式
通過調用 spdk_app_stop() 終止，或者在
spdk_app_start() 本身的初始化代碼中發生錯誤條件，在調用調用者
提供的函數之前。

### 自定義關閉回調 {#event_component_shutdown}

創建基於 SPDK 的應用程式時，用戶可以添加自定義關閉回調，該回調
將在應用程式框架開始關閉過程之前調用。
為此，在傳遞給 spdk_app_start() 的 spdk_app_opts 結構中設置 shutdown_cb 函數回調。
自定義關閉回調應在
返回以繼續應用程式關閉過程之前調用 spdk_app_stop()。
