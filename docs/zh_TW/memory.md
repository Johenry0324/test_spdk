# 從用戶空間直接記憶體訪問 (DMA) {#memory}

以下是試圖解釋為什麼傳遞給 SPDK 的所有數據緩衝區必須
使用 spdk_dma_malloc() 或其同類函數分配，以及為什麼 SPDK 依賴
DPDK 經過驗證的基礎功能來實現記憶體管理。（注意：DPDK
mbufs 在結合 SPDK 和 DPDK 功能的應用程式中使用也是安全的。）

計算平台通常將物理記憶體劃分為稱為頁面的 4KiB 段。
它們從可尋址記憶體的開頭開始將頁面從 0 編號到 N。
操作系統然後使用任意複雜的映射在這些物理頁面之上覆蓋 4KiB 虛擬記憶體頁面。
有關概述，請參閱
[虛擬記憶體](https://en.wikipedia.org/wiki/Virtual_memory)。

物理記憶體連接到通道上，其中每個記憶體通道提供
一些固定數量的帶寬。為了優化總記憶體帶寬，
物理尋址通常設置為在通道之間自動交錯。
例如，頁面 0 可能位於通道 0 上，頁面 1 位於通道 1 上，頁面 2 位於通道 2 上，等等。
這是為了順序寫入記憶體
自動利用所有可用通道。在實踐中，交錯是在比完整頁面更細粒度的級別完成的。

現代計算平台支持在其記憶體管理單元 (MMU) 內部進行虛擬到
物理轉換的硬體加速。MMU
通常支持多種不同的頁面大小。在最近的 x86_64 系統上，支持 4KiB、
2MiB 和 1GiB 頁面。通常，操作系統預設使用 4KiB 頁面。

NVMe 設備使用直接記憶體訪問 (DMA) 在系統記憶體之間傳輸數據。
具體來說，它們通過 PCI 總線發送請求數據
傳輸的訊息。在沒有 IOMMU 的情況下，這些訊息包含 *物理* 記憶體
地址。這些數據傳輸在不涉及 CPU 的情況下發生，MMU
負責使對記憶體的訪問保持一致。

NVMe 設備還可能對這些傳輸的記憶體物理佈局提出額外要求。
NVMe 1.0 規範要求所有物理
記憶體都可以通過稱為 *PRP 列表* 的東西來描述。要由
PRP 列表描述，記憶體必須具有以下屬性：

* 記憶體被分解為物理 4KiB 頁面，我們稱之為設備頁面。
* 第一個設備頁面可以是從任何 4 字節對齊的
  地址開始的部分頁面。它可以延伸到當前物理頁面的末尾，但不能
  超出。
* 如果有多個設備頁面，第一個設備頁面必須在
  物理 4KiB 頁面邊界結束。
* 最後一個設備頁面在物理 4KiB 頁面邊界開始，但不
  需要在物理 4KiB 頁面邊界結束。

規範允許設備頁面是 4KiB 以外的其他大小，但截至本文撰寫時，所有
已知設備都使用 4KiB。

NVMe 1.1 規範添加了對完全靈活的散點聚集列表的支持，
但該功能是可選的，今天可用的大多數設備都不支持它。

用戶空間驅動程式在常規進程的上下文中運行，因此可以訪問
虛擬記憶體。為了用物理
地址正確編程設備，必須實現某種地址轉換方法。

在 Linux 上最簡單的方法是從
進程內檢查 `/proc/self/pagemap`。此文件包含虛擬地址到物理地址
映射。從 Linux 4.0 開始，訪問這些映射需要 root 權限。
但是，操作系統絕對不保證虛擬到物理頁面的映射是靜態的。
操作系統無法看到 PCI 設備是否直接將數據傳輸到一組物理
地址，因此必須非常小心地協調 DMA 請求與頁面
移動。當操作系統標記頁面使得虛擬到
物理地址映射無法修改時，這稱為 **固定** 頁面。

虛擬到物理映射可能改變的原因也有幾個。
到目前為止，最常見的原因是由於頁面交換到磁盤。但是，
操作系統也會在稱為壓縮的過程中移動頁面，該過程將
相同的虛擬頁面摺疊到同一物理頁面上以節省記憶體。
某些操作系統還能夠進行透明記憶體
壓縮。熱添加額外記憶體也越來越可能，
這可能觸發物理地址重新平衡以優化交錯。

POSIX 提供了 `mlock` 調用，它強制記憶體的虛擬頁面始終
由物理頁面支持。實際上，這是禁用交換。但是，這
*不* 保證虛擬到物理地址映射是靜態的。`mlock` 調用不應與 **固定** 調用混淆，事實證明 POSIX 沒有定義用於固定記憶體的 API。
因此，分配固定記憶體的機制是特定於操作系統的。

SPDK 依賴 DPDK 來分配固定記憶體。在 Linux 上，DPDK 通過
分配 `hugepages`（預設為 2MiB）來實現這一點。Linux 內核對 hugepages 的處理與常規 4KiB 頁面不同。
具體來說，操作系統將
永遠不會更改它們的物理位置。這不是故意的，所以事情
可能在未來版本中發生變化，但今天這是真的，並且已經持續了
多年（有關面向未來的解決方案，請參閱後面關於 IOMMU 的部分）。

通過這個解釋，希望現在清楚為什麼傳遞給
SPDK 的所有數據緩衝區必須使用 spdk_dma_malloc() 或其同類函數分配。
緩衝區必須特別分配，以便它們被固定並且物理
地址是已知的。

## IOMMU 支持

許多平台包含一個稱為 I/O 記憶體
管理單元 (IOMMU) 的額外硬體組件。IOMMU 非常類似於常規 MMU，除了它
為外圍設備（即 PCI
總線上的設備）提供虛擬化地址空間。MMU 知道系統上每個進程的虛擬到物理映射，
因此 IOMMU 將特定設備與這些映射之一關聯
，然後允許用戶為其進程中的虛擬
地址分配任意 *總線地址*。PCI 設備和
系統記憶體之間的所有 DMA 操作然後通過 IOMMU 轉換，通過將總線
地址轉換為虛擬地址，然後將虛擬地址轉換為物理
地址。這允許操作系統自由修改虛擬到
物理地址映射，而不會破壞正在進行的 DMA 操作。Linux
提供了一個設備驅動程式 `vfio-pci`，它允許用戶使用
其當前進程配置 IOMMU。

這是一個面向未來的、硬體加速的解決方案，用於在用戶空間進程中執行 DMA
操作，並形成了 SPDK 和 DPDK 記憶體管理策略的長期
基礎。我們強烈建議
使用 vfio 和啟用 IOMMU 部署應用程式，這在今天完全
受支持。
